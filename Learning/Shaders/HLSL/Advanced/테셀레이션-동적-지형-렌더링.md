## GPU 기반 동적 지형 렌더링: 테셀레이션 파이프라인
이 문서는 DirectX 11의 테셀레이션 파이프라인을 활용하여, 카메라 거리에 따라 디테일 수준(LOD)이 동적으로 변화하는 광활하고 사실적인 지형을 렌더링하는 방법을 심도 있게 다룹니다.

> **따라 하기**: 코드는 셰이더 부분이며 C++ 호스트가 필요합니다. 환경·행렬 규약은 [실습 환경과 공통 규약](../0.%20실습%20환경과%20공통%20규약.md)을 먼저 읽으세요. 이 문서의 코드는 앞선 HLSL 기초·중급·고급 모듈에서 만든 구조체/상수 버퍼를 이어서 사용하며, 작성자가 직접 컴파일하지는 않았습니다.

> **호스트 요구사항**: 토폴로지를 `D3D11_PRIMITIVE_TOPOLOGY_4_CONTROL_POINT_PATCHLIST` 로 설정하고, VS/HS/DS/PS 를 모두 만들어 `HSSetShader`, `DSSetShader` 로 바인딩해야 합니다. 인덱스/정점은 지형을 이루는 **사각형 패치의 네 꼭짓점**을 `0=(u0,v0), 1=(u1,v0), 2=(u1,v1), 3=(u0,v1)` (사각형을 한 바퀴 도는 순서)로 넣습니다. 도메인 셰이더의 보간 코드가 이 순서를 가정합니다. 하이트맵은 `R16_UNORM`/`R8_UNORM` (sRGB 아님)로 읽습니다. 아래 HLSL 코드 블록 4개(VS, HS, DS, PS)는 **하나의 `.hlsl` 파일에 순서대로 이어 붙여** 사용하며, `CBufferTess` 는 HS 와 DS 가 공유합니다(상수 버퍼를 `HSSetConstantBuffers` 와 `DSSetConstantBuffers` 양쪽에 바인딩).

### 왜 테셀레이션 지형인가?
광활한 월드를 구현할 때 가장 큰 난관은 '성능'과 '디테일' 사이의 균형입니다.

* 고해상도 메시: 처음부터 수백만 개의 폴리곤으로 이루어진 지형을 사용하면 가까이서 볼 때는 디테일이 뛰어나지만, 메모리 사용량이 막대하고 렌더링 성능이 급격히 저하됩니다.

* 저해상도 메시: 멀리서 볼 때는 문제가 없지만, 가까이 다가가면 각진 지형이 그대로 드러나 몰입감을 해칩니다.

테셀레이션은 이 문제를 GPU 단에서 해결합니다. 우리는 아주 성긴(low-poly) 기본 메시만 GPU에 넘겨주고, 렌더링 파이프라인 중간에서 GPU가 직접 이 메시를 수많은 작은 삼각형으로 잘게 쪼개어 디테일을 '창조'하도록 합니다. 특히 카메라에 가까운 부분은 더 잘게, 먼 부분은 덜 잘게 쪼개어 동적 LOD를 완벽하게 구현할 수 있습니다.

### 테셀레이션 렌더링 파이프라인
테셀레이션을 사용하면 기존의 정점/픽셀 셰이더 사이에 3개의 새로운 단계가 추가됩니다.

* 정점 셰이더 (Vertex Shader): 지형을 구성하는 큰 사각형 패치(Patch)의 제어점(Control Point)들을 받아 헐 셰이더로 넘기는, 비교적 간단한 역할만 수행합니다.

* (신규) 헐 셰이더 (Hull Shader, HS): 테셀레이션의 '두뇌'입니다.

* 상수 함수 (Constant Function): 패치(Patch)가 카메라로부터 얼마나 멀리 떨어져 있는지 계산하여, 이 패치를 **얼마나 잘게 쪼갤지(Tessellation Factor)**를 결정합니다.

* 제어점 함수 (Control Point Function): 제어점 데이터를 가공하여 도메인 셰이더로 넘겨줄 준비를 합니다.

* (신규) 테셀레이터 (Tessellator): 하드웨어 고정 단계입니다. 헐 셰이더가 결정한 Tessellation Factor에 따라, 패치를 실제로 잘게 쪼개어 수많은 새로운 정점들의 '위치 정보(Barycentric Coordinate)'를 생성합니다.

* (신규) 도메인 셰이더 (Domain Shader, DS): 테셀레이션의 '아티스트'입니다. 테셀레이터가 생성한 수많은 새 정점들을 입력받아, **하이트맵(Height Map)**을 참조하여 각 정점의 최종 3D 위치(특히 높이)를 결정합니다.

* 픽셀 셰이더 (Pixel Shader): 도메인 셰이더가 완성한 최종 지형 표면에 색상과 재질을 입힙니다.

핵심 요소: 하이트맵 (Height Map)
* 하이트맵은 지형의 높낮이 정보를 담고 있는 흑백 텍스처입니다. 검은색(0)은 가장 낮은 지역을, 흰색(1)은 가장 높은 지역을 의미합니다. 도메인 셰이더는 이 텍스처를 샘플링하여 평평한 격자 위의 정점들을 위아래로 움직여(Displacement) 산과 계곡을 만들어냅니다.

### HLSL 구현
1. 정점 셰이더 (Vertex Shader)
입력된 제어점의 위치를 그대로 헐 셰이더로 전달합니다.
```hlsl
// 제어점의 입력/출력 구조체
struct VS_OUTPUT
{
    float3 Pos : POSITION;
};

VS_OUTPUT VS(float3 pos : POSITION)
{
    VS_OUTPUT output;
    output.Pos = pos;
    return output;
}
```
2. 헐 셰이더 (Hull Shader)
카메라 거리에 따라 테셀레이션 강도를 결정하는 핵심 부분입니다.
```hlsl
// 제어점 데이터를 HS -> DS로 전달하기 위한 구조체
struct HS_OUTPUT
{
    float3 Pos : POSITION;
};

// HS의 상수 함수 출력 구조체 (테셀레이션 팩터)
struct HS_CONSTANT_DATA_OUTPUT
{
    float EdgeTessFactor[4] : SV_TessFactor; // 사각형 패치의 4개 외곽선
    float InsideTessFactor[2] : SV_InsideTessFactor; // 사각형 패치의 내부
};

cbuffer CBufferTess : register(b0)
{
    float4   CameraPos;     // xyz = 카메라 월드 위치
    float4x4 ViewProj;      // 패치 좌표가 이미 월드 공간이므로 ViewProj 를 쓴다 (C++ 에서 전치)
    float4   TerrainParams; // x = TerrainSize, y = MaxHeight, z = minDist, w = maxDist
}

// 거리 -> 테셀레이션 팩터 (가까우면 64, 멀면 1)
float CalcTessFactor(float3 p)
{
    float d = distance(p, CameraPos.xyz);
    return lerp(64.0f, 1.0f, saturate((d - TerrainParams.z) / (TerrainParams.w - TerrainParams.z)));
}

// 상수 함수: 패치당 한 번 호출됨
// 중요: 인접한 패치가 공유하는 *변(edge)* 의 팩터는 두 패치에서 같은 값이 나와야 틈(crack)이 생기지 않는다.
// 그래서 패치 중심이 아니라 *변의 중점* 거리로 각 변의 팩터를 계산한다.
HS_CONSTANT_DATA_OUTPUT HSConstantFunction(InputPatch<VS_OUTPUT, 4> inputPatch)
{
    HS_CONSTANT_DATA_OUTPUT output;

    // 쿼드 도메인의 변 순서: [0]=u=0 변(제어점 0-3), [1]=v=0 변(0-1), [2]=u=1 변(1-2), [3]=v=1 변(3-2)
    float3 e0 = 0.5f * (inputPatch[0].Pos + inputPatch[3].Pos);
    float3 e1 = 0.5f * (inputPatch[0].Pos + inputPatch[1].Pos);
    float3 e2 = 0.5f * (inputPatch[1].Pos + inputPatch[2].Pos);
    float3 e3 = 0.5f * (inputPatch[3].Pos + inputPatch[2].Pos);
    float3 center = 0.25f * (inputPatch[0].Pos + inputPatch[1].Pos + inputPatch[2].Pos + inputPatch[3].Pos);

    output.EdgeTessFactor[0] = CalcTessFactor(e0);
    output.EdgeTessFactor[1] = CalcTessFactor(e1);
    output.EdgeTessFactor[2] = CalcTessFactor(e2);
    output.EdgeTessFactor[3] = CalcTessFactor(e3);

    // 내부 팩터는 중심 기준 (u 방향, v 방향)
    float inner = CalcTessFactor(center);
    output.InsideTessFactor[0] = inner;
    output.InsideTessFactor[1] = inner;
    return output;
}

// 메인 함수: 각 제어점마다 호출됨
[domain("quad")]
[partitioning("fractional_odd")] // integer 는 팩터가 바뀔 때 정점이 툭 튀는(popping) 현상이 심하다
[outputtopology("triangle_cw")]
[outputcontrolpoints(4)]
[patchconstantfunc("HSConstantFunction")]
HS_OUTPUT HS(InputPatch<VS_OUTPUT, 4> inputPatch, uint i : SV_OutputControlPointID)
{
    HS_OUTPUT output;
    output.Pos = inputPatch[i].Pos;
    return output;
}
```
3. 도메인 셰이더 (Domain Shader)
새로 생성된 정점들의 최종 위치를 하이트맵을 이용해 결정합니다.
```hlsl
Texture2D HeightMap : register(t0);
SamplerState HeightSampler : register(s0);

// 도메인 셰이더 출력 (픽셀 셰이더 입력)
struct DS_OUTPUT
{
    float4 Pos : SV_POSITION;
    float2 Tex : TEXCOORD0;
    float3 WorldPos : TEXCOORD1;
};

[domain("quad")]
DS_OUTPUT DS(HS_CONSTANT_DATA_OUTPUT hsConst, const OutputPatch<HS_OUTPUT, 4> inputPatch, float2 domainLoc : SV_DomainLocation)
{
    DS_OUTPUT output;

    // 1. 도메인 위치(domainLoc)를 이용해 패치 내의 평면상 위치(x, z)를 보간
    float3 worldPos = lerp(
        lerp(inputPatch[0].Pos, inputPatch[1].Pos, domainLoc.x),
        lerp(inputPatch[3].Pos, inputPatch[2].Pos, domainLoc.x),
        domainLoc.y
    );

    // 2. UV 좌표 계산 및 하이트맵 샘플링
    output.Tex = worldPos.xz / TerrainParams.x; // TerrainSize = 전체 지형 크기, 지형이 (0,0)~(TerrainSize,TerrainSize) 에 놓였다고 가정
    float height = HeightMap.SampleLevel(HeightSampler, output.Tex, 0).r;

    // 3. 하이트맵 값을 이용해 높이(y) 적용 (Displacement)
    worldPos.y = height * TerrainParams.y; // MaxHeight = 최대 높이

    // 4. 최종 화면 위치 계산 및 픽셀 셰이더로 데이터 전달
    output.WorldPos = worldPos;
    output.Pos = mul(float4(worldPos, 1.0f), ViewProj);
    
    return output;
}
```
4. 픽셀 셰이더 (Pixel Shader)
지형의 높이에 따라 색상을 입혀 시각화합니다.
```hlsl
float4 PS(DS_OUTPUT input) : SV_Target
{
    // 높이에 따라 색상을 다르게 표현 (낮은 곳: 녹색, 높은 곳: 흰색)
    float heightPercent = saturate(input.WorldPos.y / TerrainParams.y);
    float3 grass = float3(0.2, 0.6, 0.2);
    float3 snow = float3(1.0, 1.0, 1.0);
    
    float3 finalColor = lerp(grass, snow, pow(heightPercent, 2.0));
    
    // (여기에 텍스처 스플래팅, 조명 계산 등을 추가할 수 있음)
    
    return float4(finalColor, 1.0);
}
```
> **알아둘 점**: 이 코드는 법선을 계산하지 않아 조명을 넣을 수 없습니다. 조명을 추가하려면 DS 에서 하이트맵을 이웃 텍셀 3곳에서 샘플링해 기울기로 법선을 구하거나 PS 에서 구합니다. `TerrainParams` 는 `float4` 하나에 묶어 정렬 문제를 피했습니다.

## 다음 단계: 지형을 실전 장면으로 확장하기

아래 확장은 현재의 단일 하이트맵 지형 예제를 바탕으로 하나씩 추가합니다. 한 번에 여러 효과를 넣지 말고, 기능마다 화면 결과와 성능을 비교하세요.

1. **법선과 조명**: 이웃 하이트맵 샘플로 지형 기울기를 근사해 법선을 계산하고, 먼저 Lambert 조명으로 표면 방향이 보이도록 합니다. 평탄한 영역의 법선이 위쪽을 향하고, 경사면에서 밝기가 달라지는지 확인합니다.
2. **텍스처 스플래팅 (Texture Splatting)**: 높이와 경사도를 기준으로 잔디·흙·암석·눈 마스크를 만듭니다. 높이 경계에서 색이 갑자기 끊기지 않고, 가파른 경사면에 암석 재질이 나타나는지 확인합니다.
3. **LOD 전환과 지오모핑 (Geomorphing)**: 카메라 거리에 따라 패치의 테셀레이션 수준을 바꾸고, 인접 패치의 공유 변에서 같은 분할 기준을 사용합니다. 카메라를 천천히 이동해 경계의 균열이나 지형이 튀는 현상이 생기는지 점검합니다.
4. **프러스텀 컬링 (Frustum Culling)**: 패치 경계가 카메라 절두체 밖에 있는지 Hull Shader에서 검사하고, 보이지 않는 패치의 테셀레이션을 생략합니다. 화면 밖 패치가 사라져도 절두체 경계에서 지형이 갑자기 잘려 보이지 않는지 확인합니다.
5. **측정과 비교**: 컬링 전후의 렌더링 시간과 테셀레이션 수준을 같은 카메라 위치에서 기록합니다. 결과가 같다면 더 적은 작업으로 그려졌는지 PIX 등으로 확인합니다.

**완료 기준**: 지형의 조명 방향이 일관되고, 재질 경계가 자연스러우며, LOD 경계에 틈이 없습니다. 카메라가 보지 않는 영역은 불필요한 테셀레이션을 줄이고, 그 전후 차이를 측정 결과로 설명할 수 있습니다.

> **자료 상태**: 이 저장소에는 텍스처 스플래팅, 지오모핑, 패치 컬링을 완성형 코드로 따라 하는 문서가 없습니다. 위 항목은 확장 과제이며, 별도 코드 튜토리얼과 검증 결과를 추가해야 합니다.
